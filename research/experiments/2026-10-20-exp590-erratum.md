# Errata EXP-590 — clasificación Currier contaminada por $Q

Fecha: 20-10-2026  
Estado: **INVALID_FOR_CLAIM** para todos los resultados desglosados por clase Currier del artefacto original; reproducción corregida pendiente.

## Qué ocurrió

La versión original de scripts/exp590_daiin_position.py obtenía la etiqueta de clase con la variable IVTFF $Q. En IVTFF, $Q identifica el cuaderno/quire; la lengua Currier se representa mediante $L=A/B. Por tanto, la distribución A/B/unknown del JSON y el informe originales de EXP-590 no representa la clasificación Currier correcta.

## Alcance del defecto

- No utilizar la tabla por clase del resultado original de EXP-590 para comparar Currier A frente a B.
- Los conteos globales de tokens y de posición no dependen directamente de la clase Currier; aun así, se deben regenerar al reproducir el script para comprobar que el código y la fuente son idénticos.
- El defecto no debe ocultarse sobrescribiendo el resultado histórico. El JSON/Markdown original se conserva para trazabilidad.
- El script se corrigió para usar el parser común parse_currier_language, que solo lee $L.
- Se añadieron pruebas de regresión que cubren cabeceras con $Q y $L contradictorios y la clasificación unknown cuando falta $L.

## Criterio para cerrar la errata

1. Confirmar que GitHub Actions ejecuta las nuevas pruebas y la auditoría de metadatos.
2. Ejecutar el script corregido sobre la transcripción canónica versionada.
3. Comparar SHA-256 de la fuente con el valor esperado y comprobar las métricas globales.
4. Publicar nuevos JSON/Markdown con una versión o ruta nueva y enlazar los originales como históricos.
5. Revisar que las clases se extraen exclusivamente de $L y que el total A+B+unknown coincide con el total de ocurrencias.
6. Marcar el resultado corregido como REPRODUCED solo tras revisar el run y sus logs; no declarar VALIDATED sin controles estadísticos adicionales.
